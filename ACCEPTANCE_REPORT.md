# Validation report

Latest validation of the renamed single-library layout: **82 tests passed — 70 library tests on Java 8 (33 acceptance, 16 runtime, 21 tooling) and 12 Gradle plugin functional tests on Java 21; zero failures, errors, or skips.** `./gradlew --no-daemon spotlessApply build generatePomFileForMavenJavaPublication writeDependencyReport --write-locks -PtestJavaVersion=8` completed successfully. Formatting, compilation, plugin validation, Javadoc/source JARs, distribution assembly, and Java 8 bytecode checks passed for 44 unique runtime JARs and both sample packages. Counts are recorded in `build/verification/latest-tests.json`.

The independent repository is now `worker-packages-java`. It contains one `io.temporal:temporal-worker-packages` library with API, tooling, runtime and CLI classes, and the `io.temporal:temporal-worker-packages-gradle-plugin` build plugin. Publication metadata was generated and checked for both names. The library POM contains SDK/Jackson dependencies and excludes the CLI-only test-server dependency; the CLI distribution includes that dependency. Java packages use `io.temporal.worker.packages`, the runtime API is `WorkerPackagePlugin`, and the Gradle ID/task are `io.temporal.worker-packages`/`workerPackage`. Existing archive manifest and routing-header formats remain unchanged.

The first consolidated run exposed a private-Jackson fixture configuration left in its former test project; it now lives in the root test configuration and remains outside the host classpath. An existing intermittent replay-only factory shutdown timeout also recurred. The test harness now immediately shuts down replay-only factories, which have no polling work to drain; real started workers retain graceful draining. Its focused replay-recovery check and the complete rerun passed.

The installed CLI smoke test also passed on Java 8 using `env JAVA_HOME=/Library/Java/JavaVirtualMachines/adoptopenjdk-8.jdk/Contents/Home ./scripts/validate-cli.py`. It verifies string-version listing, validation, byte-identical repacking of the Java 21-built archive, patch packaging with canonical names and visible targets, and a worker containing only `2 → patch1 → patch2` archives. The worker selects logical version `2` without its original archive, executes `patch2`, completes workflow start/signal/result, and terminates cleanly. Latest evidence is `build/verification/cli-smoke/summary.json`. ZIP timestamps now use January 2, 1980, avoiding Java 8's extra timestamp metadata at the epoch boundary; this preserves archive bytes across the two tested JDKs.

Patch support adds optional `patchesVersion` metadata and canonical `<packageId>-<target>-<patch>.twp` filenames. Patch-only deployment and transitive patch chains execute the leaf archive while retaining original pins and activity headers. Tests cover cold replay, unchanged unrelated versions, saved histories, new logical-target selections, cross-JVM activity retries, strict unpatched checksums, competing patches, cycles, cross-package targets, filename validation, and cache snapshots. Explicit patch metadata intentionally overrides an old pinned checksum; the effective patch's own bytes are validated. Original archives may be absent, while intermediate archives are required to describe their chain edges.

Versions are now opaque strings, including Git SHAs. Hosts select a version for each new workflow through `WorkerPackagePlugin.Options.Builder.setVersionSelector`; the builder records that policy and the dispatcher invokes it inside a single side effect recording `[version, digest]`. Replays and activities use that exact pin without consulting the selector. Tests cover changing policies, cold restart, saved-history replay, preserved activity headers, null/unavailable selection failures before application code, and recovery after the host policy changes. The recovery test uses a two-second workflow-task timeout so SDK retries after repeated failures remain bounded; repeated task failures need not produce separate history failure events.

Each greeting sample builds its own archive through the production Gradle plugin. Its tests cover string and Git-SHA project versions, explicit overrides, runtime dependencies, compile-only SDK exclusion, up-to-date execution, byte-identical clean builds, invalid tokens, and dependency filename collisions. Duplicate version identifiers still fail startup globally. Diagnostics describe the selection policy and installed types without evaluating a callback. Existing SDK preferred-version providers remain unchanged.

The new manifest/header and single-side-effect pin format replace the earlier integer-version protocol. Old archives require rebuilding; old pin-history replay compatibility is outside this POC. Compilation continues to use the local sdk-java main checkout; Maven release 1.40.0 remains declared without a release compatibility check.
